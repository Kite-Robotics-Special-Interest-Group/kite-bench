# 仿真迁移：MuJoCo 数据采集（Unity 只做演示与验证）

上一版把 Unity 当仿真器用，结论是它能演示、能验证接口，但不适合做数据采集和训练：单实例、主线程绑定、没有并行环境，4 步/秒的吞吐无法支撑模仿学习或强化学习。因此采集与训练迁到 MuJoCo，Unity 保留为演示端和可视化验证。

## 1. 环境

| 项 | 值 |
| --- | --- |
| 物理引擎 | MuJoCo 3.17.0（`pip install mujoco`，Windows cp314 有轮子） |
| 机器人模型 | `mujoco_menagerie/trossen_wx250s`（Apache-2.0，与训练数据同一构型） |
| 坐标系 | ROS/Bridge 约定：x 前、y 左、z 上——和模型训练帧一致，不再需要坐标变换 |
| 代码位置 | `D:\JLU_tools\kite-sim`（原型，暂不入仓库） |

## 2. 场景

`scene.py` 用字符串拼一个场景，include 官方 `wx250s.xml`：

- 桌面 `0.9 × 0.7 m`，台面 z = 0；表面加 1 mm 青绿桌垫（贴合参考画面，避免 z-fighting 要抬高 1 mm）
- 红色方块 `4 cm`，**带 `freejoint` 的独立刚体**，质量 20 g、摩擦 1.2——可以真实被抓取、被推走
- `front` 相机：MJCF 相机，前上方约 40° 俯视，224×224
- 腕部视角：自由相机每帧跟随 `gripper_link`（位置沿夹爪前向偏移、方位角取夹爪朝向），224×224

两个视角渲染到 `out/mujoco_cams.png`，用来肉眼核对“模型看到的画面”。

## 3. 成功判定（原先问的“方块高度”）

方块是自由刚体，所以判定直接读它的位置：

```python
success = cube_z > 2 * CUBE_SIZE + 0.02   # 抬起超过 6 cm
```

配套的奖励/终止条件（RL 时用）：

| 项 | 定义 |
| --- | --- |
| 稠密奖励 | `-||ee - cube|| + 1.0 * 夹爪闭合 * 靠近 + 2.0 * cube_z` |
| 成功 | 夹爪闭合且 `cube_z > 0.06` 连续 10 帧 |
| 失败 | 方块落地滚出桌面、超时（如 300 步） |
| 终止 | 成功或超时 |

## 4. 脚本化示教（oracle）

`demo.py` 生成一条拾取轨迹：

1. 从 keyframe 复位，位置伺服开到 READY，夹爪张开（0.037）
2. 6 自由度阻尼最小二乘 IK（位置 + 朝向），把夹爪姿态锁成**自上而下**（夹爪 x 轴朝下）
3. 三段路点：方块上方 22 cm → 下降（夹爪原点比方块高 6.6 cm，指尖正好到方块中部）→ 闭合到 0.016 → 抬到 24 cm
4. 记录每步 `qpos`、`ctrl`、方块位置

实测：`cube height 0.1298 (threshold 0.060) success=True`，单条 540 步。

### 踩坑

- **include 路径**：`MjModel.from_xml_string` 解析 mesh 时按当前工作目录找 STL，会报 `Error opening file ...stl`。要把拼好的 XML **写在 `wx250s.xml` 同目录**再用 `from_xml_path` 加载。
- **夹爪初始化**：`MjData` 默认让两个手指落在 qpos ≈ 0，而关节范围是 `±0.015..0.037`，两个手指互相穿插、被接触力钉死，位置伺服**永远推不开**（`actuator_force` 有 6 N，但 qpos 反而往负方向走）。必须先用 `mj_resetDataKeyframe(model, data, 0)` 复位到 keyframe（手指 ±0.015），夹爪才正常开合。
- **指尖偏移**：`gripper_link` 原点到指尖约 6.6 cm（朝下时），目标点要按指尖算，否则整条臂会压到桌面。

## 5. 下一步

1. **批量采集**：随机化方块位置（桌面内 ±5 cm）与初始关节角，跑 200–500 条示教，同时存 `front`/`wrist` 两路 224×224 图像、proprio（末端位姿 + 夹爪）、动作（绝对末端位姿 + 夹爪）。
2. **模仿学习**：冻结 0.9B 主干，只训练动作头 + soft prompt（LoRA 级，8 GB 显存够用），损失沿用 `ee6d` 的 `position_loss / rotate6D_loss / gripper_loss`。
3. **验证**：训练后的策略回 Unity 闭环跑，用同一套 HUD（延迟、模型输出、关节、成功率）对比采集前基线；Unity 侧协议不变，只是数据来源从脚本换成微调后的权重。
4. 之后再考虑用残差动作 + PPO 在 MuJoCo 里做精修，那时吞吐可到数千步/秒。
