# 输入扰动基线（X-VLA-WidowX）

第一张扰动表：同一批观测，只改输入图像，看模型输出的动作块漂移多少。

## 设置

| 项 | 值 |
| --- | --- |
| 模型 | `2toINF/X-VLA-0.9B-WidowX`（fp32，CPU） |
| 观测 | 3 帧（episode 0000/0001/0002 的首帧，224×224 桌面视角） |
| 去噪 | `steps=5`，**固定 seed=0**（否则噪声远大于扰动本身） |
| 动作空间 | 绝对末端位姿 `[xyz(3), rot6d(6), grip(1)]` |
| 指标 | Δpos（mm，整块 30 步均值）、Δrot（测地角均值）、夹爪翻转率 |

复现：

```bash
python -m kitebench.sim.collect --episodes 3 --out out/episodes
python -m kitebench.eval --episodes out/episodes \
  --model <path-to-X-VLA-WidowX> --frames 3 --steps 5 --seed 0 \
  --out out/perturb_seeded.md
```

## 为什么必须固定 seed

第一次跑的时候没固定去噪初值，同一张干净图两次推理的漂移是 **11.8 mm / 4.6° / 夹爪翻转 12%**——把亮度 ±10% 的效应（约 1–5 mm）完全淹没了。固定 `torch.manual_seed(0)` 后噪声底为 **0.00**，表里的数字才归因于输入本身。

## 读法

1. **模糊最致命**：3 px 就把动作目标推偏 70 mm，而且 3 px 之后饱和。对应真实场景就是失焦、镜头脏、运动模糊——这条要在部署清单里排第一。
2. **遮挡改变夹爪决策**：10% 面积的矩形遮挡让夹爪翻转率从 0 飙到 **31%**；`occlude_arm`（手臂挡住画面下半）也有 14%。相比位置漂移，夹爪翻转是更危险的失效——它直接决定抓不抓。
3. **光度变化几乎无害**：亮度 ±20%、对比度 ±20%、gamma 0.85–1.2 都在 12 mm 以内、夹爪翻转 ≤2%。这条可以放心，不必为照明去调数据。
4. **几何扰动是稳定劣化**：平移/缩放/旋转 17–27 mm，量级一致，说明模型对相机的刚体偏移比较敏感但对方向不敏感。
5. **噪声是线性劣化**：σ 从 5 到 20，漂移基本线性（7→24 mm），可以作为标定曲线的参考。

## 局限（别把这张表当结论）

- 只有 **3 帧**，每格是 3 次推理的均值，趋势可信、数值会有 ±20% 的波动
- `steps=5` 为省时间，正式对比应与部署一致（板端是 10）
- 单 seed；要报误差棒得跑 3–5 个 seed
- 动作漂移是**代理指标**，不等于任务失败；闭环成功率见 M4
