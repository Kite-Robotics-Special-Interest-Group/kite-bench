2026-10-27 决定停止仿真侧投入，直接上真机。这是本仓库的结项文档：**哪些能带走、哪些别再投入、真机上会重复遇到什么**。

## 二、能直接带走的东西

1. **扰动评测工具**（`perturb.py` + `metrics.py`）——不依赖仿真，**可以直接作用在真机图像上**，用来测"光照/模糊/遮挡时策略退化的程度"。这是最值钱的遗留物。
2. **数据格式**：`episodes/NNNN/{meta.json, action.npy, proprio.npy, obs/*.png}`，动作 `[ee_xyz(3), rot6d(6), grip(1)]`、20 Hz。真机采数据直接沿用，训练代码不用改。
3. **训练管线**（`features.py` + `train.py`）：冻结视觉语言主干、只训后 8 层 + soft prompt，8 GB 显存够用，一次训练 20 分钟。
4. **回放闸门**：评测任何策略前，先回放示教关节轨迹，成功率 ≥90% 才允许评策略。这个判据在真机同样适用（用来排除"控制链路坏了被误读成模型不行"）。

## 三、别再投入的

1. **仿真里的外观/分拣打磨**：外观一变就失效，说明瓶颈是数据覆盖，不是仿真精度；换成真机后这个问题会以另一种形式出现（光照、背景、物体多样），但**用真机数据解决更直接**。
2. **在 Windows 上折腾官方 SimplerEnv**：SAPIEN 平台限制，不是配置问题。要用只能上独立 Linux + NVIDIA。
3. **当前的微调权重**：`head_v7.pt` 等只对训练场景有效，别指望迁到真机。

## 四、真机上会重复遇到的问题（现在就能预防）

| 仿真里的坑 | 真机上的对应物 | 预防 |
| --- | --- | --- |
| 夹爪标签单位错（米 vs 0/1） | 真机里夹爪是"开/合指令"还是"位置/电流"，别混 | 采集时就明确并写进 meta |
| 动作时域与动作块不匹配 | 控制频率与模型 chunk 长度不匹配，表现为"反应迟钝/过冲" | 先定控制频率（建议 10–20 Hz），再定 chunk |
| IK 分支歧义 | 真机用解析 IK 或直接关节空间，避免多解 | 优先关节空间动作，或固定臂形约束 |
| 相机被机械臂自己挡住 | 同样存在 | 机位和任务区先做可见性检查 |
| 外观一变就失效 | 换工位/换光照 | 采集时就做外观随机化（换位置、换灯） |

## 六、如果要重启仿真线

按这个顺序，别从外观开始：

1. 先确认评测链路（回放闸门 ≥90%）
2. 再扩数据（每场景 300–500 条，含外观随机化）
3. 最后才调外观/场景复杂度——**外观是最后一步，不是第一步**
